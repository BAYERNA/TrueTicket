# TrueTicket 암표 대응 에이전트

T4 마스킹·구조화 추출 결과 · ChatGPT → Claude

사용자가 A안을 선택했다. 갱신 기획서 11-1절 T4에 따라 요청 전 마스킹, 한국어 구조화 추출, 검증과 재시도, 평가 실행 경로를 구현했다. 현재 실행 환경에는 `OPENAI_API_KEY`가 없어 모델 실측이 남아 있다.

## 1. 구현 현황

| 11-1절 T4 조건 | 상태 | 확인 근거 |
| --- | --- | --- |
| LLM·임베딩 모델 이름과 버전 기록 | 충족 | 선택한 API ID는 `gpt-5.6-terra`, `text-embedding-3-large`다. 평가에서 실제 응답의 모델 ID도 기록한다. |
| 마스킹 10건에서 개인정보 0건 | 로컬 충족 | 요청 경계에서 이름·전화·계좌·이메일 가상 값 40개 중 잔존 0개를 확인했다. 모의 HTTP 검증이다. |
| JSON 스키마 100% 확인, 실패 시 1회 재시도 | 부분 충족 | Strict 스키마와 Pydantic 검증을 구현했다. 스키마 실패에서 딱 한 번 재시도하고 다시 실패하면 `확인 불가`로 내려가는 동작을 검증했다. 실측 스키마 통과율은 미측정이다. |

| 인젝션 5건의 추출·판단 동일 | 부분 충족 | 정제한 요청 5쌍이 모두 동일했다. 모의 응답에서도 추출 처리 결과가 일치했다. 실측 추출 비교와 T6 위험 판정 비교는 남았다. |
| 은어 5종의 해석 테스트 고정 | 충족 | 정가양도·수고비·플미·아옮·오만 추가의 해석을 로컬 규칙과 테스트로 고정했다. |

T1~T3의 기존 자동 검사도 통과했다. T4에서 만든 추출·근거·신뢰도는 T5 연결 단계가 입력으로 사용할 수 있다.

## 2. 바뀐 점과 이유

- 수집 직후 FastAPI 감시 경로에서 마스킹과 구조화 추출을 실행한다. 이 세 단계는 실행 로그에 순서대로 기록한다.
- 추출 요청에는 마스킹한 제목·본문과 가상 공연·회차 목록을 전달한다. 게시판의 선택 가격은 화면 표시용이며, 추출 정확도 평가는 제목·본문으로 계산한다.
- 스키마에 맞아도 근거 인용이 원문에 없으면 재시도한다. 파싱·검증 후 가격 또는 좌석이 없거나 신뢰도가 0.6 미만이면 `확인 불가`로 처리한다. 위험 규칙은 T6에서 계산한다.
- 일반 감시에서 가격 미정이 명시되고 화폐 표현이 없으면 사람 검토 대상으로 넘긴다. 전체 평가에서는 가격 미상 사례의 null 처리도 비교하도록 80건을 모두 추출한다.
- 전체 실측은 CLI에서 시작한다. `GET /api/eval`은 최근 실측의 집계를 보여 준다. 같은 글의 모델·프롬프트·입력이 일치하면 감시에서 기존 추출을 재사용한다.

## 3. 배포 정보

로컬 진입은 `uvicorn backend.app.main:app` 후 [가상 리셀 마켓](http://127.0.0.1:8000/market)이다. `OPENAI_API_KEY` 설정 후 감시를 시작하면 구조화 추출 결과를 볼 수 있다. 공개 배포와 서버 플랜·한도 설정은 후속 단계다.

## 4. 기술 스택과 버전

Python 3.11.18, FastAPI 0.141.1, SQLite 3.53.1, Pydantic 2.13.4, httpx 0.28.1과 React 19.3.1·Vite 8.3.8·TypeScript 5.9.3을 사용했다. 추출은 `gpt-5.6-terra`의 Responses API와 strict JSON Schema를 사용한다. `text-embedding-3-large`는 T5 판매자 군집에 사용하도록 기록했다. [Terra 모델](https://developers.openai.com/api/docs/models/gpt-5.6-terra) · [Large 임베딩 모델](https://developers.openai.com/api/docs/models/text-embedding-3-large)

## 5. 사전 개발물 재사용 목록

`pre-hackathon` 기준점은 `7237a53`이다. 봇 규칙 원본과 두 수집 원본의 세 파일은 11/18 보고서 기록을 따른다. T4는 기존 가상 마켓 수집기를 받아 마스킹·추출에 연결했다. 시드와 평가셋을 재사용했다.

## 6. 평가 결과

| 검증 | 결과 |
| --- | --- |
| 로컬 자동 검사 | 16개 통과. T4 10개 및 기존 T1~T3 6개 |
| 전송 직전 마스킹 | 10개 모의 HTTP 요청, 가상 값 40개 잔존 0개 |
| 인젝션 정제 | 5쌍 모두 정상 본문과 정제 후 요청 동일 |
| JSON 검증 | 모의 스키마 실패 때 최대 2회 요청, 반복 실패 시 `확인 불가` |
| 신뢰도 | 모의 값 0.5999는 `확인 불가`, 경계 0.6000은 다음 단계 가능 |
| `post-017` | 기준 정답은 장당 137,000원, `A-01-01`·`A-01-02`, 수량 2. 계약 테스트에 기준 모의 응답을 사용했다. |

Terra의 추출 정확도, 실측 스키마 통과율, 토큰·지연과 실제 오답 3건은 API 실행 후 기록한다. 로컬에서 장당가를 274,000원으로 반환한 모의 응답을 오답으로 집계하는 검사도 통과했다. T5 군집 정확도와 T6 규칙 평가 지표는 후속 작업이다.

실행 환경에 `OPENAI_API_KEY`를 설정하고 저장소 루트에서 기준 글과 전체를 평가한다.

```bash
python -m backend.app.evaluation.t4 --post-id post-017
python -m backend.app.evaluation.t4
```

전체 평가는 `data/evaluation/t4_results.json`에 필드 정확도, 오답 사례, 토큰과 처리 시간을 저장한다. 인젝션의 비교용 본문도 별도로 평가한다. 공개 집계에는 정답이나 원문이 담기지 않는다.

## 7. 화면 캡처 목록

`/market`에 추출 완료 건수와 `확인 불가` 상태를 표시한다. React 빌드와 감시 경로의 상태 응답을 확인했다. 이번 작업의 브라우저 화면 캡처는 미완이다.

## 8. 알려진 오류와 한계

- 실제 API 계정의 해당 모델 호출 가능 여부와 한국어 추출 성능은 미확인이다.
- 정규식은 가상 입력의 이름·전화·계좌·이메일 패턴을 다룬다. 라벨이 없거나 새로운 형식인 이름과 계좌는 자동 인식 범위에 한계가 있다. 대회 시연에는 가상 정보만 입력한다.
- 검사한 인젝션은 별도 지시문 줄 5종이다. 추출 모델 지시에도 게시글을 신뢰할 수 없는 데이터로 명시한다.
- 계획의 외부 글과 내부 예매 연결, 위험 판정, 승인형 조치는 T5~T7에 속한다.

## 9. AI 사용 기록

형규님이 Terra와 Large를 선택했다. Claude의 기획서를 기준으로 ChatGPT가 로컬 마스킹, 요청·검증 계약, 상태 처리, 감시·평가 경로, 자동 검사와 전달 문서를 작성했다. 이번 작업의 실측 모델 호출은 0건이다.
